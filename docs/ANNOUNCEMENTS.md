# 公告维护

## 导航入口与列表

导航栏的公告入口仅显示图标，桌面端位于深浅色模式切换按钮右侧，手机端保留导航栏公告图标。按钮提供名称提示和无障碍名称，点击后在图标下方展开公告浮层，配色跟随网站主题。浮层右边沿尽量与图标对齐，窄屏自动限宽，低高度视口内可滚动；不遮暗背景，也不锁定页面滚动。图标在响应式布局切换后被隐藏时，浮层自动收起。

再次点击图标、点击或聚焦浮层外部、按 Esc 均可收起列表；使用关闭按钮或 Esc 后焦点回到公告图标。Markdown 公告条目收起浮层并打开原有 `BaseDialog` 正文弹窗，正文保留来源按钮、滚动和焦点管理，不提供返回列表按钮。关闭正文后回到页面，焦点回到公告图标；需要再次查看列表时重新点击图标。没有 Markdown 公告时，显示勾选图标和空列表提示。

公告列表条目保留键盘焦点提示，使用按钮内侧的 2px 描边，避免首项或滚动后条目的焦点框被滚动容器裁切；进站模态列表和导航浮层共用此样式。

## 独立公告栏

页面公告栏恢复为导航栏下方的独立横幅，沿用原有样式和“查看”跳转按钮，不再加入公告列表。组件为 `src/components/SiteAnnouncement.vue`，配置维护在 `src/locales/announcement.ts`：`enabled` 控制横幅显隐，`link` 配置目标地址；`messages` 的 `label`、`body`、`action` 分别提供无障碍名称、正文和按钮文案。简体中文和英文分别配置，繁体中文沿用简体文案自动转换。

横幅不参与列表的置顶、发布日期和红点提醒；关闭横幅不会隐藏 Markdown 公告列表。嵌入页面和管理页面不显示横幅。

## Markdown 公告列表

Markdown 条目由 `src/data/announcements.ts` 读取 `src/content/announcements/` 下的所有 `.md`，包含子目录。文件相对于公告目录的路径去掉 `.md` 后作为 ID，例如 `official-account.md` 的 ID 是 `official-account`。

新增公告只需在该目录新增 Markdown 文件，并提供 YAML 元数据 `title`。列表条目和正文窗口均读取此标题，不需要逐项修改导航或列表代码。简中、繁中和英文的导航及操作文案已提供，公告标题与正文仍使用 Markdown 中的原文。

## 自定义图标

在每份公告的 YAML 元数据中配置 `icon`，以下写法三选一：

```yaml
icon: 'lucide:bell' # Iconify 图标名
# icon: '/imgs/logo/logo_128.png' # public 目录下的图片
# icon: 'https://api.iconify.design/lucide/heart.svg?color=%234f8cff' # HTTPS 图片
```

本地图片放在 `public/` 下，路径从站点根目录 `/` 开始，不包含 `public`，也不使用相对于 Markdown 文件的 `./` 路径。外部图片使用可直接访问的 HTTP(S) 地址，部署时推荐 HTTPS。图片按 20×20 像素等比显示并保留原配色，Iconify 图标沿用站点主题色。

省略 `icon`、设为 `null` 或空字符串时，置顶公告仍用图钉，普通公告仍用喇叭。自定义图标优先于默认图标，但不会隐藏“置顶”文字标识或改变排序；只修改图标不会重新触发红点或进站弹窗。进站模态列表与导航浮层共用此配置，修改后需重新构建部署。

## 置顶公告

Markdown 公告在 YAML 元数据中设置 `pinned: true` 即可置顶，省略或设为 `false` 时不置顶。

列表分为置顶组和普通组，置顶组在前，同一组内按文件 ID 排序。支持同时置顶多条公告；未配置自定义图标时，置顶公告左侧使用图钉图标，普通公告使用喇叭图标。配置自定义图标后仍保留简中“置顶”、繁中“置頂”或英文“Pinned”文字标识。

只调整置顶状态不会更改发布日期、进站弹窗的关闭记忆或重新触发红点。修改配置后需重新构建部署。下方 Markdown 示例中的 `pinned: true` 表示启用置顶。

## 红点提醒

桌面和手机公告图标在有未查看公告时显示红点，悬停提示和无障碍名称也会标明存在未查看公告。点击图标或进站自动打开列表，即将列表中的所有 Markdown 公告标记为已查看并清除红点，不要求逐条打开正文；再次刷新仍保持已查看状态。

已查看版本保存在当前浏览器的 `localStorage` 键 `site-announcements:seen` 中，各浏览器独立。切换语言或删除公告不会产生新提醒。新增 Markdown 公告，或修改其标题、`publishedAt`，会再次提醒；只修改正文不会自动产生新提醒，如需重新提醒，应按重新发布处理并更新发布日期。独立公告栏的开关、文案或跳转地址变化均不影响列表红点。

红点和进站模态列表共用已查看记录，不再单独记录某篇公告是否关闭。存储记录损坏时会将当前公告视为未查看；本地存储不可用时仍可在当前页面会话标记已查看，刷新后可能再次提醒。

## 发布日期

在每份 Markdown 公告的 YAML 元数据中配置 `publishedAt`，使用带引号的 `YYYY-MM-DD` 字符串，与标题分开维护。

日期单独显示在公告标题下方并左对齐，替代原“查看详情”提示；简体、繁体中文使用年月日格式，英文使用英文月份格式。`<time datetime>` 保留原始日期。未填写日期的公告不显示时间，不会用当前日期补齐；列表按置顶分组，组内按文件 ID 排序，不按日期排序。

现有账号说明日期 `2026-09-26` 来自正文落款。

## 内容与编译

当前账号说明维护在 `src/content/announcements/official-account.md`。公告是仓库维护的可信静态内容，不接收用户提交，也不经过 CMS 发布。

`unplugin-vue-markdown` 在构建时将公告转换为 Vue 组件，再交给 Vue 插件编译。两者的 Markdown 匹配规则都仅覆盖公告目录，普通内容目录不会因此参与组件化编译，原有 `.vue` 文件照常处理。浏览器不额外加载公告 Markdown 解析器。

已开启 `markdownOptions.html`，正文可使用 `<p align="right">` 等 HTML 排版。修改或新增公告后需重新构建部署。

## 来源按钮

来源链接显示在正文窗口底部，与确认按钮并排；列表窗口不显示来源链接。通过每份公告顶部的 YAML 元数据配置：

```yaml
---
title: VM汉化组官方新账号启用说明
publishedAt: '2026-09-26'
pinned: true
icon: 'lucide:bell'
sourceButton:
  text: 查看 Bilibili 原公告
  link: https://www.bilibili.com/opus/1251946408080048130
---
```

配置 `sourceButton`（包含 `text` 和 `link`）时显示来源按钮；省略整个配置或设为 `null` 时隐藏。查看来源在新窗口打开链接，不关闭正文或改变已查看状态。

## 进站公告列表弹窗

简体中文且存在未查看公告时，进站使用 `BaseDialog` 在视口中央显示公告列表，而非导航按钮下的小浮层。公告列表保留右上角关闭按钮，进入正文后隐藏，返回列表时重新显示；保留公共组件的遮罩、页面滚动锁、背景隔离与焦点循环，支持 Esc、底部确认按钮和点击遮罩关闭。点击条目后在同一个 `BaseDialog` 内显示对应正文和标题，正文从顶部显示并接收焦点。由此入口打开的正文左上角通过 `header-start` 插槽提供“返回公告列表”，沿用最初的蓝色文字、透明背景、无描边及左箭头样式，手机端也保留完整文字，标题位于返回按钮下方。底部仅保留可选的来源链接和确认按钮。返回时保持弹窗打开，并将焦点恢复到刚查看的条目，可以继续选择其他公告。关闭整个弹窗仍回到页面，不会重新打开列表。

导航按钮仍打开原有非模态浮层，不显示遮罩或锁定页面滚动。从该浮层打开的正文不显示“返回公告列表”。两种列表共用 `src/components/AnnouncementList.vue`，保持图标、置顶标识和发布日期一致。

`/admin`、`/agreement`、`/privacy` 及其子路径不自动弹出，嵌入页面不显示公告入口。进入允许的页面或切换到简体中文时，若仍有未查看公告，也会自动弹出模态列表。

打开进站模态列表或导航浮层均将当前全部公告标记为已查看；关闭列表或正文不会另写关闭记录。没有未查看公告时，刷新不会重复自动弹出，但仍可通过导航按钮重新阅读。新增公告或修改标题、发布日期后，会按未查看规则再次触发，不再依赖指定的单篇公告 ID。
